# 独立六题v3：核心与稳健性重构

## 为什么重构

v2将“所有未知额外字段也必须递归拒绝NaN”作为每个中间API的硬要求。它是本地改编层新增的通用工程要求，并非全部上游共同标准。大量候选完成了业务和JSON加载器校验，却因这一共享缺口失去整题成功，混淆了业务/编排难度与通用防御性验证。

## 保留的核心

六题目标、业务决策、排序/阈值/集合规则、输入夹具、contract、文件依赖、四类结构保持。业务使用字段类型/范围、合法空集、声明的无解处理、错误引用、实际数值有限性、JSON接口、输出和最终报告仍须正确；不得修改保护文件或硬编码样例。

## 从核心拆出的内容

原api/*/nonfinite-ignored-field不再出现在核心检查集合。未知额外字段递归NaN/Infinity拒绝保留为可选稳健性诊断，具有独立检查数、摘要、结果和运行入口；不扣核心reward，也不决定核心E/M/H。

## 探针改进

当输入是恰好{name,result}的封装时，探针放在result业务对象内，保持外层结构。每个组件配备直接/嵌套有限值正例控制，以及NaN、正负Infinity反例。不得通过破坏封装制造伪非有限数测试。业务真正消费的数值字段另有核心非有限数案例，避免一并放松真实域约束。

## 指标和版本

核心完成率与核心reward用于主评测；稳健性单独报告；全规格完成率表示两者全过。core6/MPxx是本版评分键，旧medium/MPxx仍属于v2。当前六题历史reward上限均为2，难度标签另据本轮五次结果确定，避免事后调整权重。

v2任务、26题旧发布及旧模型运行均保留。本版先做作者参考解、初始实现、业务错误、保护篡改和“核心正确但忽略额外元数据”的控制验收，再冻结新题面并进行全新30次模型复测。作者控制结果和模型结果分别归档。
