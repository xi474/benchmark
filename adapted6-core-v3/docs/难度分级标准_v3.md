# v3 核心难度与独立稳健性标准

固定Terminus 2 + DeepSeek V4 Pro普通模式，每题五次；核心成功要求业务、域有效性、接口、文件依赖、集成及完整性检查全部通过。E=4–5/5，M=2–3/5，H=0–1/5。标签是本模型/harness/预算下的条件实测档，不代表跨模型绝对难度。结构依据另行保留，失败原因必须说明。

未知额外字段的非有限数检查只计optional robustness；有限额外字段控制、NaN、+Infinity、-Infinity及直接/嵌套两种形态共8例/组件，21组件共168例。核心难度、核心reward不被这些项目否决。全规格完成率为核心和可选稳健性全部通过，同时报告。

核心reward = 历史固定档位权重上限 × 通过核心verifier数 / 固定核心verifier总数；支持小数、六位舍入。当前六题沿用M上限2，事前冻结，不随观测档位回改。稳健性单独给出通过数/总数/比例，不与核心reward相加。篡改保护文件使核心reward为0，独立稳健性也标完整性无效。

实际使用的业务数值非有限仍为核心错误；无数值业务字段的组件不强加人为数值字段。严格JSON加载器与有限JSON输出继续作为核心接口要求。未使用额外字段中的非有限数接受或拒绝均不影响核心分档。

Harbor读取的reward和all_checks_passed均表示核心；JSON同时包含robustness_pass_ratio、robustness_all_checks_passed和strict_all_checks_passed。检查列表/摘要、分组和权重在正式运行前冻结。旧v2成绩不覆盖，旧候选换评分的离线诊断不记作v3新模型运行。

稳健性总通过率包含有限字段正例控制；同时单列nonfinite-extra通过率，避免将仅通过控制样例解释为能拒绝非有限数。所有控制和非有限数探针均通过才算稳健性全过。
