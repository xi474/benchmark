# journal

All required fields below are mandatory (including empty lists/maps). IDs match [a-z][a-z0-9_]{0,15} exactly: do not strip, lowercase or coerce. Integers exclude bool. All integers are nonnegative unless explicitly stated otherwise. Reject NaN/Infinity anywhere, including extra fields. Reject missing fields, invalid types/ranges, duplicate IDs, unknown references and cyclic prerequisite graphs with ValueError, never leak KeyError. Record IDs are unique within their own list; different lists have separate namespaces. Extra fields may be ignored after finite-value validation. normalize returns a new canonical object containing only specified fields: record lists sorted by id, ID lists sorted and unique, nested effect/contents lists sorted by their reference key. No input or contract mutation. Both normalize(payload) and solve(payload, contract) independently accept and validate raw input. The contract object is file/API metadata, not business input. Use an exact algorithm for bounded input sizes. Return the bare result object with exactly the specified keys, types, ordering and tie rules; no name/result envelope.
audit.verify(payload, result, contract) must validate raw input and return a bool. For valid payload it must accept a correct result and reject malformed, infeasible or numerically inconsistent results. It must recompute feasibility and totals from input and the proposed decision, rather than unconditionally accepting, trusting totals, or simply delegating to solve. It need not prove global optimality: focused and final tests separately compare solve against exact optima. For invalid payload it raises ValueError; malformed result returns False. It must not mutate input/result/contract. All APIs use only the Python standard library.

Input {accounts:[{id,balance,version}],events:[{id,seq,tx,kind,...}]}; <=12 accounts,80 events. kind exactly begin/debit/credit/commit/abort. debit/credit additionally require account,amount,expected_version; account reference must exist even for events that will not execute. Events with identical ID and identical canonical fields are deduplicated; conflicting duplicate ID raises ValueError. Nonoperation canonical fields are only id,seq,tx,kind. Sort canonical events by (seq,id); other record lists by id. Replay in that order. begin snapshots ALL current committed balances/versions. Repeated begin for an existing tx emits rejected_event duplicate_begin and never resets it, even if terminal. Any other event on missing/nonopen tx emits not_open. A debit/credit with expected_version != its account's BEGIN snapshot version poisons tx with version_mismatch, emits rejected_event version_mismatch and stages no delta. Otherwise stage signed delta, including a zero operation that still touches the account. abort sets status aborted,reason empty, no commit. commit checks in order: poisoned=>version_mismatch; any touched account's committed current version differs from BEGIN snapshot=>version_conflict; any resulting committed balance<0=>insufficient_funds. Failed commit sets rejected+reason, applying no changes. Successful commit applies net deltas atomically and increments each touched account version ONCE. Empty commit is valid. Open transactions remain open. Return {accounts:[{id,balance,version}],transactions:[{tx,status,reason}],rejected_events:[{id,reason}]}. Transaction status open/committed/aborted/rejected, reason empty except rejected. accounts sorted by id, transactions by tx, rejected_events in replay order. Transaction commit failures are in transactions, not rejected_events. Only malformed input raises; legitimate event rejections are output.
