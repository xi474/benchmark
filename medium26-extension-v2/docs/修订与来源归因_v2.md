# Medium26 v2：修订与来源归因

日期：2026-11-09。v2以现有业务组件、输入、契约和评分语义为基准修正规格；保留v1发布及其基线。

**本次六项冲突都能定位到本地改编后的新增接口、范围删减或说明未同步，不能归咎于上游原题。** 其中多项上游要求原本明确，但本地投影后没有同步修改概要。

## 逐题归因与修复

### MP04｜多格式用户合并与完整冲突报告

- 上游原题：Terminal-Bench原题要求表格式合并输出和冲突报告，没有本地新增的三个解析器result.records接口。来源：[multi-source-data-merger](https://github.com/harbor-framework/terminal-bench-2/blob/2fd12b88aafdd04a52c298e3940bcb189f9766d6/multi-source-data-merger/instruction.md)。
- 问题引入位置：本地新建中间schema时，公开规则只写records按ID排序，遗漏容器类型。
- v2修复：三路records统一明确为按id字符串字典序排列的对象数组，空结果为[]，汇合接口读取同一schema。
- v2任务目标：读取JSON、CSV、JSONL用户源，分别输出records数组，再按字段优先级合并用户目录和完整冲突证据。

### MP08｜节日照片迁移后发送与缺失报告

- 上游原题：GAIA2原题明确要求在2020年照片中搜索多个节日，并含女儿定位、指定照片发送和独立清理。来源：[scenario_universe_28_wy635e](https://huggingface.co/datasets/meta-agents-research-environments/gaia2/viewer/mini/validation?row=110)。
- 问题引入位置：本地已将输入投影成photos:{path,festival}，但概要保留年份识别及清理要求，未声明投影范围。
- v2修复：明确photos由数据准备阶段限定目标年份并附节日标注；本地只做节日分类、迁移和全部迁移照片的发送清单，不解析年份、不另做清理或身份搜索。
- v2任务目标：处理已限定目标年份并附节日标注的照片元数据，按所需节日分类、迁移，再用新路径生成发送清单和缺失报告；本地子集不解析年份、不执行独立清理。

### MP09｜两场座谈会、群邀请与物资采购

- 上游原题：GAIA2原题明确第一场空档、下月第二个周日、群标题/活跃日期筛选及最贵可用商品。来源：[scenario_universe_29_8hgfug](https://huggingface.co/datasets/meta-agents-research-environments/gaia2/viewer/mini/validation?row=65)。
- 问题引入位置：本地改为分钟窗口、显式群ID和评分优先采购，概要却仍沿用原题规则。
- v2修复：概要与组件统一为最早两场分钟时段、显式群ID并集、最高评分再低价和ID；不宣称保留第二周日及最贵商品规则。
- v2任务目标：按给定分钟窗口选择最早两场可用时段，按显式群ID归并成员，按评分、价格和ID选择物资；两场齐备后生成活动及通知计划。

### MP10｜晚宴计划、联系人定位与餐具采购

- 上游原题：GAIA2原题明确向两位对象分别发邮件。没有本地dinner_checkout中间结果的items/unavailable排序接口。来源：[scenario_universe_26_135a24](https://huggingface.co/datasets/meta-agents-research-environments/gaia2/viewer/mini/validation?row=66)。
- 问题引入位置：本地简化成单一主要联系人却未同步概要；新增采购结果数组时未公开参考实现的排序约定。
- v2修复：明确单一主要联系人、guest_count仅为餐具份数；items按kind、unavailable按字符串字典序升序。
- v2任务目标：按给定weekday和hour计算下一次晚宴，定位最近匹配话题会话中的单一主要联系人，为guest_count人数匹配餐具并生成一次采购计划。

### MP11｜取消会面、研讨会叫车与图书采购

- 上游原题：GAIA2原题明确要求hardcover精装书，并指定提前30分钟叫车。来源：[scenario_universe_23_2gyolt](https://huggingface.co/datasets/meta-agents-research-environments/gaia2/viewer/mini/validation?row=73)。
- 问题引入位置：本地图书输入和筛选没有装帧，接送提前量已参数化，但概要仍保留精装与固定30分钟。
- v2修复：公开受限改编不测装帧；按输入关键词、语言、预算、评分价格选择；接送使用lead_minutes。
- v2任务目标：按组织者与日期窗口取消会面并生成通知，按lead_minutes计算研讨会接送时刻，再按关键词、语言、预算及评分价格规则选择图书；本地子集不按装帧筛选。

### MP24｜大学任职、在读人数与国家集合查询

- 上游原题：Terminal-Bench原题明确full professors，原知识图及查询包含职称/role概念。来源：[sparql-university](https://github.com/harbor-framework/terminal-bench-2/blob/2fd12b88aafdd04a52c298e3940bcb189f9766d6/sparql-university/instruction.md)。
- 问题引入位置：本地将人员投影成professors:{id,departments}，未声明名单已按职称预筛，概要却要求正式教授筛选。
- v2修复：明确输入名单已预筛为正式教授，本地不实现职称判断；保留EU任职、逐部门在读人数与国家集合规则。
- v2任务目标：在输入已预筛为正式教授的名单中，按EU任职及至少一个单独任职部门在读人数超过10的条件查询，并返回全部任职国家。

## MP24上游问题与本次问题须分开

此前来源审查已发现，源参考查询按教授跨部门COUNT DISTINCT，可能将两个各6人的部门合并成12人；原文字要求至少一个单独部门>10。v1已按逐部门门槛明确本地规则。这个来源口径差异与本次“职称预筛范围没写清”是不同问题。原查询分析属于文本和集合反例核对，不冒充完整SPARQL环境复现。
