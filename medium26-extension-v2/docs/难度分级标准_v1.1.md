# 当前难度分级标准 v1.1

> 归档日期：2026-11-04。本规范用于本项目的任务设计与候选筛选。E/M/H 是相对分级；本批已加入参考解与功能验收；难度仍为设计预估，尚无模型通过率或并行提速证据。

## 1. 分级锚点与适用范围

沿用项目约定：原仓库的 **14 个唯一任务**作为简单档的设计参考，经过修改、评审并发布的 **16 个精确规格版 v4 任务**作为难档的设计参考，在两者之间补充中等任务。

本地 manifest 核对结果：原包有 18 个 entry、14 个唯一任务名；精确规格版 v4 有 16 个 entry、16 个唯一任务名。因此“原 14 题”不是将 18 个 entry 当成 18 个独立任务。

这两个锚点表示项目内的设计定位，不代表原 14 题只包含简单算法，也不代表所有模型都会觉得 v4 的每题都难。SWE、Pro、Terminal、GAIA2 原有的难度标签或人类耗时不能直接移植到改造后的任务。

## 2. E / M / H 的操作性定义

| 档位 | 主要特征 | 可以包含 | 不应作为分级理由 |
| --- | --- | --- | --- |
| E：简单 | 少量明确规则或标准算法，接口和状态组合成本较低，局部正确通常较容易组成整体正确 | 过滤、稳定排序、有限域置换、基本对象协议；也可有规模较小的标准图/动态规划算法 | 文件很多、输入很长、来自知名难基准 |
| M：中等 | 标准算法有真实组合，或存在有限状态/跨模块不变量；需要正确汇合多个有用结果，但规则和搜索范围可明确限制 | 多格式归并、跨表关联、编解码与元数据一致、有限 AST 分析、日历区间与通知计划、固定规则的引用校验 | 简单题拆成很多函数、加入一个最终哈希、单纯增大数据量 |
| H：难 | 核心算法或多个约束之间的交互显著增加推理成本；局部正确难以保证整体正确，可能需要复杂搜索、程序语义或长期状态处理 | 多约束精确优化、自解释器、逆向上下文编码；或撤销/继承/版本/窗口/补偿等多种状态约束跨模块交织 | 歧义、缺失依赖、版本漂移、隐藏规则、偶然超时 |

**中等档的关键是“有实质组合，但范围受控”。** 不能因为一个任务有三个并行分支就自动归 M；也不能因为业务听起来复杂就归 H。

## 3. 四个独立审查轴

每题记录 A、S、C、I。0/1/2 是描述档，不是实测分数；目前不做加权求和，也不设一个没有实验支持的总分阈值。

| 轴 | 0：较低 | 1：中等设计范围 | 2：较高 |
| --- | --- | --- | --- |
| A：算法 | 直接匹配、转换、单次排序或局部对象协议 | 标准解析、集合/关联/图遍历、有限语法、区间规划、编解码等有明确边界的组合 | 多约束候选搜索显著膨胀、复杂解释语义、逆编码或其他较难核心算法 |
| S：业务状态 | 单次静态快照或纯计算；算法内部 visited/memo 不因此算复杂业务状态 | 少量共享状态、快照隔离、批次提交、幂等或有限的调用前后不变量 | 多轮澄清、异步取消与补偿、撤销祖先/版本迁移/时序规则等相互影响的状态 |
| C：依赖耦合 | 模块较独立，集成主要是收集输出 | 一至两个有因果意义的局部汇合，或共享规则的一致性 | 深层、交叉、动态解锁和多不变量同时关联；上游选择显著改变下游可行解 |
| I：接口集成 | 单接口、单表示或少量固定字段 | 几个稳定 API/格式之间转换、精确边界和错误规则明确 | 多后端/多协议/多版本兼容及跨接口状态相互影响 |

### 判断门槛

- **E 候选**：主要成本仍集中在少量局部规则，S/C/I 很低。一个复杂名字的业务字段不构成升档理由。
- **M 候选**：至少有一个实质的 A1、S1 或 C1；常见组合是标准算法 + C1/I1，或者局部状态不变量 + 稳定多接口。必须能写出使常见错误实现失败的具体反例。
- **H 候选**：核心 A2，或高状态与交叉耦合共同主导工作量。应根据实际边界审查，不能机械规定“用了回溯一定 H”。
- 如果某候选确实需要 A2/S2/C2 才成立，本批优先删减需求或移到难档；不能保留全部需求只改标签。
- 如果任务只是若干独立的 E 小题机械拼接、各分支结果互不消费，也不能仅凭模块数定为 M。

## 4. 本批中等任务的范围约束

1. 环境以 Python 3.11 标准库、小型本地文件与静态快照为目标；无需真实训练、GPU、账号、常驻服务或完整 ARE 栈。
2. 算法限定为清楚的标准方法与有限语法，不要求全局最优搜索或通用语言/协议完整兼容。
3. 日历题处理时间记录，不进行墙钟等待。动态多轮反馈、精确实时触发和复杂补偿不在本批主范围。
4. 接口提前公开，数据类型、缺失值、排序、平局、日期边界和错误条件在 TASK 中写明。
5. 需要多个结果形成真正可消费的产物，而不是只交几份互不相关答案。
6. 主候选通常可建议 3–4 个有内容的实现单元；这是分工目标，不是难度硬门槛或已测并行收益。

## 5. 难度与并行潜力必须分开

| 并行层面 | 应记录什么 | 不能混淆成什么 |
| --- | --- | --- |
| 开发侧 | 哪些模块有各自规则、边界、文件写入区与稳定接口，能独立实现或用小样例验证 | 多几个 parse/render 包装函数、几行复制代码 |
| 运行侧 | 哪些业务链或产物能同时计算，哪些必须等上游结果 | 有多个代码文件就保证能同时运行 |
| 批量侧 | 不同记录、收件人、日期或分片是否可分区处理 | 100 个联系人就是 100 个独立开发任务 |
| 验证侧 | 哪些独立 oracle/性质检查可并行 | 把 verifier 的测试分支算成被测任务的开发并行度 |

本批“优先”表示作者判断存在较清楚的分工潜力；“条件候选”表示仍需确认模块工作量、共享前置、来源语义或改造幅度。两者都以 M 为设计目标，均未测得提速。

### 一个实现单元应满足的条件

- 有独立且非空泛的规则和边界，不只是读取一次 JSON 或转发一个字段。
- 输出被其他模块或最终产物实际使用。
- 公共契约明确，能在其他模块未完成时用固定小样例独立实现和验证。
- 有合理的代码写入边界，避免多个 Agent 必须同时修改一个核心函数。
- 即使符合这些条件，仍需实验判断任务规模是否足以覆盖并行协调成本。

## 6. 质量门槛先于难度标签

任何档位都要满足同样的质量门槛：

1. TASK、输入、参考解、verify 的语义一致；没有靠隐藏测试补写规则。
2. 环境可重复建立；日期、版本和随机性可固定。
3. 初始/空实现失败，参考解通过，典型错误实现被拒绝；本发布作者验收见review/validation_report.json。
4. 公开 smoke 与正式评分分开；可信 oracle 和输入不能由候选修改。
5. 独立动作的合法换序应被接受；必要的动作偏序、对象 ID、状态和禁止副作用应验证。
6. 任务级、代码/输入生成器级、语义级与任务族相关性都要检查；不同来源或不同拓扑不自动代表不同任务。

**规格歧义、缺失环境、原参考解错误和 LLM judge 不稳定属于质量问题，不是更高难度。** 例如本次大学知识图谱来源存在“单个部门人数”与参考查询汇总口径差异，必须先明确本地语义，不能将猜测口径当算法挑战。

## 7. 代表性例子

| 例子 | 当前定位 | 判断依据 |
| --- | --- | --- |
| 前轮 P07：只做多层稳定导出排序 | E，不纳入本批中等主选 | 层次很多，核心仍是标准排序及开关兼容 |
| MP04：三格式用户合并 | M 目标 | 独立格式规则、字段存在性/优先级和完整冲突证据需要一致 |
| MP03：三种挂载语法的受控版本 | 删减后 M 目标 | 保留异构语法与来源归并，去掉真实 OS、UUID、多层回退、超时 |
| MP02：单轴分片拼接 | 删减后 M，条件候选 | 保留数值/坐标对应，去掉多轴和重叠冲突，运行并行仍有限 |
| v4 API 下线任务 | H 设计锚点 | 通知覆盖与资源受限精确排程相互影响，局部贪心不够 |
| v4 身份联邦任务 | H 设计锚点 | 会话生命周期、祖先撤销、组继承与拒绝优先跨模块交互 |
| 前轮 T02：Scheme 自解释 | H，留在难档 | 自解释层次、词法环境、eval/apply 与 I/O 语义共同约束 |

P07、T02 是前轮公开基准候选的编号，分别来自 SWE-bench Pro、Terminal-Bench，不是原仓库 14 个任务的编号。这些是项目设计判断，不是已经证明的模型能力排名。

## 8. 后续如何校准

- 固定模型/版本、Agent 框架、工具、任务输入、时间与 token 预算、机器条件和正式计分口径。
- 使用简单/难的既有锚点和中等原型同场比较；建议每题多次运行，而不是只看一次成败。
- 分别观察完成率、失败类型、求解时间、token/费用、环境错误；不把环境崩溃计成算法难度。
- 并行收益另做单 Agent 与并行 Agent 的受控对照，检查实际重叠与协调成本。
- 若原型普遍只有局部小修就成功，考虑降 E；若受控范围仍普遍需要复杂搜索或长期状态修复，考虑升 H 或继续删减。
- 在得到实验分布前，不把“80%/40%”之类未经本项目校准的固定阈值当正式标准。

## 9. 本次范围与版本承诺

本规范与 26 题实现版一并归档。新增候选、实际删减、语义修订、参考解或模型配置变化时，应更新版本和逐题理由。当前的逐题 A/S/C/I 记录见候选总览及结构化数据；它们是设计档位，不是测试得分。
