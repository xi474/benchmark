# Synthetic spacecraft groundlink budget

Implement `python -m project.cli INPUT.json OUTPUT.json`, preserving input bytes and writing sorted-key compact JSON plus final newline. The rules model a toy contact scheduler, not real spacecraft operations.

Input has integer `switch_cooldown`, `contacts`, `packets`. Contact IDs are unique. A contact has `id,station,craft,band,group,start,end,rate` where time window is `[start,end)` and rate is positive units per tick. Packets have unique `id,craft,band,release,deadline,size,priority,requires`; sizes are positive, prerequisite IDs exist and form a DAG, and deadline is exclusive. A prerequisite completed at tick `t` has completion time `t+1`, so dependent packets can first transmit at tick `t+1`. Partial packet transmission persists as backlog. A packet only transmits on a matching craft and band contact, at ticks `release<=tick<deadline`. A contact with no currently eligible backlog **does not reserve** its station, craft or interference group.

Run integer ticks from the minimum contact start through maximum contact end minus one. At each tick, form candidate contacts that are active, positive rate and have at least one eligible packet. For each candidate, sort its eligible packets by `(-priority,deadline,id)`. Sort candidates by `(-top eligible packet priority,station,contact id)`; greedily select contacts that do not conflict with previously selected ones. At most one selected contact per station, craft, and interference group per tick. For a station's last **used** contact `(band,last_tick)`, switching to a different band is disallowed when `current_tick-last_tick <= switch_cooldown`; same band has no cooldown. After selection, transmit each chosen contact's rate greedily down its precomputed eligible packet list, allowing partial packets. Record a contact as used only when at least one unit is sent. Packet completion time is first `tick+1` when its remaining units hit zero.

Output packet rows sorted by ID as `id,delivered,unmet,completion` (null if incomplete), selected contact rows in tick/selection order as `tick,contact`, and transmission rows as `tick,contact,packet,units` in execution order. Audit `requested,sent,unmet,conserved`, with `conserved` checking requested = sent + unmet. Empty contacts/packets are valid. Public fixture and hidden cases vary contact conflicts, nonproductive contacts, cooldown, prerequisite unlocking, deadline boundaries, partial transmissions and ties. Choose your own implementation workflow.
