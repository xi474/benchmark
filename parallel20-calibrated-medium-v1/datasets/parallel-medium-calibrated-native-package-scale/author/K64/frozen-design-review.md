# 包依赖闭包的中等规模对照 K64

来源为300题库63号。K63完整五次严格通过0/5，五次都在第12例超时；其中三次其余11例全部通过，另两次还有真实的循环依赖/新鲜度/最小冲突错误。因此保留K63原版难档及全部记录，另建一个开发期规模对照，不把运行超时重算为通过。

K64只把公开规格最大目录从24包、12根缩为12包、6根，并将第12例独立根—叶分量由12对改为6对，精确可行配置仍为6^6=46656。前11个核心业务样本完全相同。动态required闭包、peer不自动安装、特性门控、合法循环、旧锁变动数优先、全体可行解计数与最小基数冲突全部保留；不是删掉核心算法或提高API时限。评分仍12核心+4交付、总reward2、完整交付占50%。5次全新Terminus2＋V4 Pro普通模式，保持2 CPU/3072MiB/90秒API/3600秒/2M预算。

最小反例仍是A1/B1依赖C1、A2/B2依赖C2，且A2有特性控制的peer D。peer不能把D拉进闭包；关闭特性又产生两种可行版本配置。A2/B1根组合导致二根最小冲突；单独每根却可行。另有相互依赖的A/B1和A/B2合法循环，必须选全局新鲜度最优版本，不能按首次DFS发现的闭环停止优化。

A2/S0/C2/I1，结构H，预计3/5，目标实测M。A2是版本选择与动态闭包/peer语义耦合，标准独立逐包最新版本不可行；C2是根/特性改变另一个包的候选版本和可行域；I1是有序三元版本及半开区间。搜索内部赋值不是业务状态机，记S0。分量解析、特性约束、旧锁差异可并行预处理，独立依赖分量并行求值，再合并计数和全局最优锁；不可行时根子集可并行复核。

这是看过K63成绩后的、明确记录的开发期规模校准；不是未触碰的测试集，也不把新旧试次混合。相同来源题族最多接纳一个版本。若五次仍易或难，不通过改档凑数。两套求解器、128微型全赋值穷举及6^6闭式核验先于任何模型调用，原题、原判题器和旧成绩都不改写。任意同优锁和任意最小基数冲突都应接受。
