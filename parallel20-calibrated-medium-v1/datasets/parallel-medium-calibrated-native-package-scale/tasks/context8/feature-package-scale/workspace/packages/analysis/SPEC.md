# Feature-gated package resolution and minimum root conflict

request has config and catalog. This is a synthetic dependency format, not a real registry. config has roots,features,prior. roots lists distinct {package,min,max} root requests; features lists enabled feature strings; prior maps known package IDs to three-integer versions, possibly no longer offered. catalog lists distinct {package,versions} packages. Each nonempty versions list has distinct {version,deps} entries. Each dependency is {package,min,max,kind,feature}. kind is 'required' or 'peer'; feature is null or a feature string. A version is [major,minor,patch], integers 0–9, compared lexicographically. A bound is null (unbounded) or a version; the interval is min <= version < max. References are valid. There are at most 12 packages, 4 versions per package and 6 roots. All inputs are valid finite data; no malformed-input rejection, network package manager, external solver or byte-format behavior is required.

Select no version or exactly one offered version per package. Every root must be selected within its interval. A dependency is active when feature is null or enabled. Starting from roots, repeatedly add targets of active REQUIRED dependencies from versions of packages already in the set. Every reached package must be selected within all active required constraints. A PEER does NOT pull its target into this closure: its target must already belong to the required closure and its selected version must satisfy the peer interval. No package outside that closure may be selected. Cycles are legal if all these constraints hold. Distinct complete package-to-version-or-unselected assignments count separately; processing order does not.

feasible_count counts ALL feasible complete assignments, before optimization. For a feasible selection changes counts selected packages whose version differs from prior.get(package), plus prior packages now unselected. freshness is the sum of 100*major+10*minor+patch of selected versions. First minimize changes, then maximize freshness. Return ANY selection tied on these two objectives, without an ID tie-break.

Return exactly {status,selected,active_dependencies,prior_deltas,score,feasible_count,minimal_root_conflict}. For ready status, selected is [{package,version},...]; active_dependencies has one {source,target,kind,feature} row for each active dependency row from selected versions, including peer rows. prior_deltas has {package,prior,selected} for each differing package in the union of prior and selected; a missing side is null. score is {changes,freshness}. feasible_count is an exact integer without a modulus; minimal_root_conflict is []. All these reports must describe the returned selection. List and key order is immaterial, but retain distinct active dependency rows.

If full roots are infeasible, use status:'blocked', selected:[],active_dependencies:[],prior_deltas:[],score:null,feasible_count:0. minimal_root_conflict must contain ANY smallest-cardinality subset of original root package IDs that is itself infeasible, treating exactly those requests with their ORIGINAL intervals as the entire root list. Minimum cardinality is stronger than merely inclusion-minimal. No ID tie-break is imposed. Empty roots always admit the empty selection, even with a prior lock; a blocked full request therefore has a nonempty conflict.

Public example: A1 requires C1, A2 requires C2 and has a peer D enabled only by turbo. B1 requires C1, B2 requires C2. C offers 1 and 2; D offers 1. Here A1 denotes version [1,0,0], and C1 constraints are [1,0,0] <= C < [2,0,0]. Roots A,B are unbounded; prior is A2/B1/C1. With turbo enabled D is not in the required closure, so only A1/B1/C1 is feasible: count1, changes1, freshness300. Disabling turbo gives two feasible assignments but the same optimal lock. Adding D as a root makes the peer satisfiable. Alternatively disabling turbo and constraining roots to A2 and B1 creates a two-root minimum conflict: each root alone is satisfiable, together they impose incompatible C versions. Treating the peer as an automatic install or choosing each package's latest version is incorrect.
