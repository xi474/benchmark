# Synthetic saga compensation planner

Implement `/app/workspace/project` so `python -m project.cli input.json output.json` works. Input has `actions` (0–12), each `{id,deps,resource,forward,compensate}`. IDs are unique nonempty ASCII; deps are distinct IDs forming a DAG. Resource is a nonempty ASCII string. `forward` and `compensate` are nonempty boolean arrays of length 1–3; each value is the result of that action's successive attempts. An action stops retrying once an attempt succeeds or its array is exhausted. The compensator is run only for actions whose forward action succeeded. Input action order is arbitrary.

Run forward scheduling in integer rounds. An action is ready when all deps succeeded and it has not succeeded or exhausted attempts. At each round, scan ready IDs sorted lexically and select greedily at most one per resource; all selected attempts execute in that round. Record selected attempts by ID as `{id,attempt,success}` where attempt starts at 1. If any selected forward action exhausts its attempts with failure, finish the **entire current round**, then abort forward scheduling. `failed_action` is the lexicographically smallest exhausted action in that round. No later forward rounds execute. If all actions succeed (including an empty action set), status is `committed` and no compensation runs.

After an abort, compensate every forward-successful action. A pending compensator is ready when every forward-successful dependent (transitively or directly) has finished its own compensation attempts, whether successful or exhausted. Thus rollback follows reverse dependency order. At each rollback round, greedily choose ready IDs sorted lexically with distinct resources and run one attempt each. Retried compensators may run in later rounds. Continue until every successful forward action has a successful or exhausted compensator. Status is `rolled_back` if all compensators succeed, otherwise `rollback_incomplete`; `unresolved` lists exhausted compensator IDs sorted. Even if a child compensator exhausts, its ancestor is allowed to proceed in a later round.

Output exactly `{status,failed_action,forward_rounds,compensation_rounds,unresolved}`. `failed_action` is JSON null for committed status. Each rounds field is an array of sorted action-attempt arrays. Serialize sorted object keys, compact JSON, final newline; do not modify input. Standard library only. Hidden cases include parallel waves, resource collision, retries, simultaneous terminal failures, mid-wave success at abort, and reverse-order rollback. No Agent workflow is required.
