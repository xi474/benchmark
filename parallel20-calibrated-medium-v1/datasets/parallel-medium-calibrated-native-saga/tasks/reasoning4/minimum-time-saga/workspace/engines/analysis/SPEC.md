# Minimum-time saga scheduling with retries and reverse compensation

This is a finite offline planning problem with known attempt outcomes, not a live transaction service. actions lists 2–9 distinct {id,deps,resource,forward,compensate,forward_time,compensation_time} actions. deps is a dependency DAG of valid action IDs. Each resource name denotes one exclusive resource per batch. forward and compensate are nonempty boolean arrays of length 1–3: results of successive attempts of that action in that phase. Stop retrying that phase after its first success or after its array is exhausted. forward_time and compensation_time are positive integers1–9, constant per attempt in their phase. All inputs are well formed and the DAG is acyclic. No network, randomness, wall clock, malformed-input or byte-format behavior is required.

initial_attempts maps some action IDs to the number of ALREADY executed forward attempts. Missing means0. This is a valid resumable checkpoint: any previously attempted action's dependencies have already succeeded; its counter is within its result array; a previous success is always its last attempt and is never retried; no already-exhausted forward failure is present. Such prior time is sunk and NOT included in the answer. A prior success DOES belong to the set that must be compensated if a later action aborts. initial_attempts may be empty.

In the forward phase an action is ready if all dependencies succeeded and it has neither succeeded nor exhausted attempts. Choose ANY nonempty subset of ready actions with distinct resources. The entire batch starts together and completes at a barrier; elapsed time is the MAXIMUM forward_time among selected actions. Only after the entire batch completes can the next batch start. Increment each selected attempt counter and apply its next boolean result. All successes in that batch are recorded, even if another selected action fails. If ANY selected forward action just exhausts its result array with failure, finish the WHOLE batch, abort forward scheduling, and record ALL exhausted failures from that aborting batch. No later forward batch may execute. Otherwise continue; all-success is committed and requires no compensation. You cannot choose an idle batch or deliberately abort without an exhausted forward failure.

After abort, compensate EVERY forward-successful action, including prior-checkpoint successes and successes in the aborting batch. A pending compensator is ready only after every forward-successful dependent has finished its compensation attempts, either successfully OR by exhausting them. Direct dependency checks suffice to implement this reverse order. Choose any nonempty ready subset with distinct resources; increment its compensation counters and apply known outcomes. Batch time is MAXIMUM compensation_time in it. Retry failures in later batches until success or exhaustion. A child's exhausted compensator does NOT prevent its ancestors from proceeding. Continue until all required compensators finish. Status is rolled_back if all succeed, rollback_incomplete otherwise; unresolved lists their exhausted failures. Resources are reusable in later batches; nothing spans two batches.

Minimize the TOTAL REMAINING elapsed time of forward plus any compensation batches until committed/rolled_back/rollback_incomplete. Outcomes are known to the planner. Do not optimize the status name separately; different equal-time valid schedules may produce different rollback sets or statuses. All attempted work and required compensation must be represented. There is no ID tie-break and no requirement to run every ready action in one batch: temporary restraint can improve later parallelism or avoid unnecessary abort cleanup.

Return exactly {minimum_time,forward_batches,compensation_batches,status,failed_actions,unresolved}. Each batches field is an ordered list of NONEMPTY lists of action IDs; order inside a batch is irrelevant. A repeated action in a later batch is a retry and is legal only if not yet successful/exhausted. failed_actions is [] for committed or the complete set of exhausted forward failures in the aborting batch. unresolved is [] for committed/rolled_back or the exhausted compensators. Return ANY minimum-time legal trace; the verifier independently replays it, including retry history, barriers, resource use, whole-wave abort, reverse order and final status. List order is irrelevant for failed_actions/unresolved.

Public example: a uses X for3, b uses X for1, c depends on b and uses Y for3; all forward/compensation arrays are [true], initially none attempted. Lexically greedy a,b,c takes7. Optimal forward_batches is [[b],[a,c]], minimum_time4, committed, no compensation or failures. A retry example has a forward [false,true] at time2 and compensation [false,true] at time3; b depends on a, forward [false,false] at time1. Total time is4+2+6=12, rolled_back. If a's first failed attempt already appears in initial_attempts, only10 time remains. If a successful child exhausts its compensator, its parent must still be compensated afterwards.
