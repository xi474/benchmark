# Synthetic microgrid restoration

Implement `/app/workspace/project` so `python -m project.cli input.json output.json` works. The input describes a radial forest of assets. Each asset has a unique `id`, `parent` (another ID or `null`), `repair_at` period, integer `priority`, integer `battery_initial`, `battery_capacity`, `battery_discharge_limit`, and arrays `demand` and `solar` of length `periods`. Roots are connected to the grid from `repair_at` onward. Nonroots are connected only when their own line and every ancestor line has been repaired. Input order is arbitrary and the parent graph is acyclic. The top-level `grid_capacity` array also has length `periods`. All quantities are nonnegative integers, `battery_initial <= battery_capacity`, and `repair_at` may equal `periods` (not repaired during this run).

For each period, determine connectivity. For each asset, use local solar toward local demand first: `solar_used=min(solar,demand)`. Before grid allocation, charge its battery with surplus solar: `solar_charge=min(battery_capacity-battery_before, solar-solar_used)`; unused surplus is `solar_curtailed`. Allocate that period's shared grid capacity to *connected* assets in descending priority, then ascending ID, toward `demand-solar_used`; each allocation is `grid_used=min(remaining_grid, residual_demand)`. Disconnected assets receive zero grid. Finally discharge each asset's battery toward its remaining demand, capped by `battery_discharge_limit` and available battery. `served=solar_used+grid_used+battery_discharge`; `unserved=demand-served`; `battery_final=battery_before+solar_charge-battery_discharge`. This final battery becomes the next period's starting battery. No grid charging, sharing of solar, negative energy, or allocation beyond demand is permitted.

Output JSON has exactly `periods` and `summary`. Each period object has `t`, `assets` sorted by ID, and `grid_unused`. An asset row has exactly `id`, `connected`, `demand`, `solar`, `battery_before`, `solar_used`, `solar_charge`, `solar_curtailed`, `grid_used`, `battery_discharge`, `battery_final`, `served`, `unserved`. `summary` has integer totals `demand`, `served`, `unserved`, `solar_used`, `solar_curtailed`, `grid_used`, `weighted_served`, `battery_initial`, `battery_final`. `weighted_served` is the sum of `priority*served` for every asset-period. Global energy balance must satisfy `battery_initial + total_solar + grid_used = served + battery_final + solar_curtailed` (where total_solar is summed from all rows). Also `demand=served+unserved`. Serialize deterministically with sorted object keys, compact separators and final newline; do not change input. Standard library only.

The public example is in `/app/workspace/fixtures/public/input`. Hidden tests vary repair cascades, priority ties, solar surpluses, disconnected island battery depletion, zero capacity and long period sequences. This is a synthetic coding exercise, not operational electrical engineering advice. No particular Agent workflow is required.
