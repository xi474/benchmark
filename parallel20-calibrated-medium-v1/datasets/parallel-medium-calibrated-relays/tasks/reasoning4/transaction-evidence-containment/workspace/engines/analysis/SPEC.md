# Containing a dependency from a disputed transaction to a consumer

The snapshot has initial (initially existing keys), transactions and queries. Each committed transaction has id, start, commit, a positive rollback impact, writes (key names), reads (key and claimed writer ID or null), and scans (prefix and list of seen keys). Transaction IDs and commit times are unique. A null claimed writer denotes the initial value or no version. Read claims are evidence and may differ from the snapshot-visible writer.

Derive directed evidence links between distinct transactions. WR links the claimed non-null writer to the reader. WW links consecutive writers of each key in increasing commit order. RW links a point reader to every other writer of that key whose commit is at least the reader's start. For each key originally absent that a scan omitted despite matching its prefix, PHANTOM links scanner to the first writer of that key if that writer committed at or after the scanner's start. Coexisting links may have several kinds.

For each query only links of the listed kinds participate. Contain propagation from its from transaction to its distinct to transaction by removing a subset of all other non-protected transactions and their incident links from this evidence graph. Evidence was captured at audit time and is not regenerated after containment. Endpoints and protected transactions cannot be removed. The cost is the sum of impacts of removed transactions, each counted once across all propagation routes. Cycles and overlapping routes are permitted.

Return {containment:{query_id:result}}. If no allowed removal can separate the two endpoints, result is null. Otherwise return {impact,required}, the minimum total rollback impact and all transactions included in every minimum-impact removal set. A list in any order represents required. If already separated the impact is zero and the list empty. This question concerns propagation between the queried endpoints only.
