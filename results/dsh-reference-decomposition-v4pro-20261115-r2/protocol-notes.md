# 协议异常与是否需要重测

本说明回答的是DSH R2参考分工试验中的`study_protocol_incomplete`，不将它等同于DSH原生Agent Team协议错误、HTTP400或正式评分器失败。

## 已证实的发生链

唯一该标签试次是**L114多Agent第一次**。原始Harbor A类API为**12/12**，结果保留；Agent非零终态及研究比较未完成也同时保留。

1. 本地研究权限检查把一段读取冻结输入的shell命令当作写操作拒绝，形成新的C3错误检查点。这属于实验控制层过宽匹配，不证明DSH没有委派能力。
2. runtime实际签发的证据引用中对应片段是`...IC28...`，模型第一次提交成`...IC26...`。严格引用验证拒绝了它。R2已把合法ID放进工具schema，但这不能保证模型总会按enum输出正确实参；runtime仍需验证。
3. 第二次提交修正了该ID，却缺少必填`candidate_work`，工具参数校验失败。这里只确认实际报出的缺失字段，不假定其他字段都正确。
4. 记录门禁要求每个检查点最多两次回复内提交合格记录。两次均未成功后，原生事件明确记录`two_decision_responses_without_accepted_record`，继而报告`study_protocol_incomplete`。
5. 子Agent随后仍完成独立参考并回传。父已处在未完成协议状态，后续C4收件决定也未补齐，候选比较为0轮。最终已签发7个检查点、5个获合格记录；C3为2/3、C4为0/1。C5未触发／检测未知，不把它算作已触发失败。

因此不能只归咎于模型，也不能只归咎于基础设施：**本地误拦制造了额外交互，模型又出现实参错误，而强制门禁把记录失败升级成了流程中止。**这也说明schema提示改善了输入可发现性，但没有根除脆弱的失败策略。

## 对结果的影响

- 正式12/12仍是实际交付物的成绩，无需重新评分，也不应改成0。
- 该次已真实创建子Agent且有独立工作；但它不是完成了参考比较的正常协作案例，不能用于无混杂的时间／成本收益主张。
- 记录中止、后续收尾和评分等待均保留在完整E2E及成本内；不删除异常后再宣称多Agent更快。
- 本轮已有M103第二次的修复—复验闭环，以及六次真实子创建。因此不需要为证明“能力存在”而重跑全部试次。

## 是否重测

**发布本轮探索性结果：不必重测。**如实发表全部attempt、缺分和控制层限制即可；不能声称决定性整体提升。

**要形成严格的性能比较：需要先修正实验层，再独立配对重测。**先离线核验合法只读命令、拒绝后的恢复、两次失败策略及收件检查点；保留模型自行决定与真实实参，不能替模型伪造记录。若更改影响两组，最小复验也应以新的S/M配对进行，不能只挑多Agent成功补跑替换旧异常。总体效果结论还需要多题、多次重复，单对pilot不足以证明稳定收益。

原R1/R2成绩、门禁失败和未知用量永久保留。**本次只有报告发布授权，没有新增付费重测授权；未启动新trial。**E112第二次的Verifier超时和M103第一次的运输超时是另外两类问题，不与本协议异常混写。
