## 二、Codex/DSH 的领域缺口补偿策略（trace 证据）

### Codex（C039 因果推断 14/14、MS11 14/14）
1. **公开样例逆向工程**：「derive the rule that produces [[X,Y],[Y,Z]] for the public case, and generalize sensibly」——把 PUBLIC_EXPECTED 当参考实现，枚举候选规则（Rule A/B），用公开期望验证后再泛化。
2. **手工数学推演**：题面公式逐字实现（残差方差 Cyy−CyP·CPP⁻¹·CPy、BIC、未舍入值、9 位小数平局、字典序），并手算验证公开样例。
3. **独立暴力参考实现对拍**：「cross-check with a brute-force reference」——写复杂度高但正确的第二实现来验证主实现的枚举。
4. **自建 tolerance 比较器**：MS11 里写 `same(actual, expected, tolerance)` 递归比较器，发现 min/max 匹配反了（"This is the OPPOSITE of what I derived!"）→ 修正。
5. 读组件 README 找参考提示。

### DSH（C033 MIPS 18/18）
1. **规格清单转录**：把题面当成规范文档，列出全部约束再实现（寄存器约定、r0=0、32 位回绕、延迟槽、syscall 号表、BSS 补零、inspect 语义……），写成 MIPS32 子集解释器。
2. 大量 bash 迭代 + edit 局部修改（105 bash / 57 edit），边跑边修。

### 共同模式
- **把"公开样例 + 题面公式"当作免费的、正确的期望来源**——用它验证实现、反推规则；
- **第二实现对拍**（暴力参考）而非"同一实现自评"；
- 题面其实**给了完整规格/公式**——C033 给了完整指令子集与系统调用表，C039 给了完整回归公式与干预规则。所谓"领域知识缺口"，大半是**规格转录与验证纪律的缺口**。

## 三、对之前结论的修正

此前判定"这 6 题期望不可从题面判定、是能力天花板"**部分错误**：C033/C039/MS11 的题面包含可判定的完整规格——Codex/DSH 用"公开样例对拍 + 规格清单"就能翻正。真正不可判定的只剩 C011（生产计划约束）、C049（训练流水）、C058（失败恢复语义）这类**题面确实是高层语义**的题（三系统在这三题上都没有严格通过）。

## 四、SP 改进建议（与现有机制挂接）

1. **公开样例字段级对拍（最高杠杆）**：现在 output_guard 只回 pass/fail，模型看不到 diff。改为把 public_check 的 expected vs actual 做**逐字段 diff 回给模型**（复用 v19/v20 的 MP-diagnostic diff 格式）。C039 的 intervened_edges、MS11 的 min/max 反转都是靠 diff 推导的——这相当于把 Codex 的逆向工程能力交给 SP。
2. **规格清单模式（门控 v3）**：counterexample gate 的第 1 条从「schema 字段规则」升级为「把题面每个约束句转录为实现清单，逐条勾选」——DSH 的 MIPS 清单模式，把"读漏一句"类失败结构性地堵掉。
3. **第二实现对拍步骤**：门控中加一步「对关键算法写简单暴力参考实现对拍」（复杂度换正确性）——Codex 的 brute-force 模式，专门打"枚举/DAG/匹配"类错误（C039/C058/MS11 全是这类）。
4. **公开期望作为反例第一来源**：反例门控先测公开样例（期望免费且正确），再自造边界反例——纠正 v2 只靠自造反例的盲区。

预期收益题：C033 已由 v24 翻正；上述改进瞄准 C039、MS11（三系统中已有人翻正、可判定）；C011/C049/C058 仍需更高层手段（题面确实欠规格，或 thinking/检索增强）。
