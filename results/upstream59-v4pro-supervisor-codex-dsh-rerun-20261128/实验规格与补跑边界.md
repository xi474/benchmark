# Upstream59 · Codex 与 DSH 完整性修复补跑

本轮用于补齐与官方 Supervisor 的同题对照。原矩阵的 13 格在 Agent 首次修改业务代码前读到了别题的 `contract.json`。13 格的原始评分均在完整性门禁处结束，未执行功能检查。原始 attempt、零分回执、请求账本和异常标签保留。

## 固定规格

- 数据集为 Upstream59 v2.1.0，冻结包 SHA-256 为 `a57c75131a14b9860507f91c8d17da9e7a4b79c548ea9f8dfac90806d972f9fc`。题面、评分器、权限、原生策略和模型路由沿用原批次。
- DeepSeek V4 Pro 普通模式，实际请求关闭推理。最多同时运行 6 个 Harbor trial，批内 HTTP 并发上限 4。
- 每格一次新 attempt，沿用单次输出 32,768 tokens、每格 $3 估算请求准入上限、累计已观测 2,000,000 tokens 后停止放行下一请求，以及连续 6 个相同模型动作后隔离的原批策略。整批沿用原预算策略。Harbor 和控制器均不对已消费格自动重试。
- `delivery-bonus-50-v1` 逐题复算。严格通过和登记核心检查通过率各占一半，交付完整性作为门槛，并按冻结难度权重计分。核心 API 通过率使用 A 组核心转换用例，单独列出。

## 补跑与合并边界

- 补跑资格以原生 trace 中可复核的工作区串题为依据。低分、模型未完成、输出触顶、累计上限或运行超时各自保留原态。单凭这些终态无需补跑。
- 模型前校验 `/app` 的全文件清单、SHA-256、题号和实际题面。评分前校验 Harbor 加载的 `/tests`、`registry.json`、`release-registry.json` 和保护文件哈希。对已知路径上的错误字节使用对应题的冻结文件恢复并复验。目录清单或题号仍无法匹配时停止该阶段。禁止在解题阶段加载评分资产。
- 正式放行前，离线复现七对源题错配及两条 Harbor 原生安装和评分路径。离线验收只执行本地故障注入，无模型请求。
- 其他 105 个 Codex 和 DSH 题位以及其余 Harness 的 59 题矩阵均使用原选定记录。补跑结果必须有两端身份回执、实际请求模式、评分与独立复核一致且用量可核对，按登记规则选入对照。新试次失败或无有效分时保留原记录并单列缺口。补跑分数高低不影响选择规则。
- 更新报告时同时列修复前后矩阵、13 格各自的旧与新记录、正式评分与运行终态、完整 E2E、tokens 和统一峰价估算成本。所选试次成本与为获取结果而消耗的全部运行费用分开列。
